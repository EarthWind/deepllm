# 04 · 预训练：让预测误差改变参数

[← 上一章](03-模型内部.md) · [返回目录](README.md) · [下一章 →](05-后训练与适配.md)

## 1. 训练目标只有一句话，但会重复很多次

自回归语言模型把序列概率分解为：

$$p_\theta(x_1,\ldots,x_T)=\prod_{t=1}^{T}p_\theta(x_t\mid x_{<t})$$

用负对数似然训练，忽略不参与损失的位置：

$$\mathcal L(\theta)=-\frac{1}{|S|}\sum_{t\in S}\log p_\theta(x_t\mid x_{<t})$$

`S` 是有效标签位置集合。真实下一个 token 的概率越低，对应损失越大。它不需要每条文本额外标注“标准答案”，因为文本自身的后续 token 就提供了监督信号。

这一目标要求模型利用词法、语法、篇章和事实关联来改善预测，因而可以形成多种可迁移能力。但预测目标本身不保证事实正确，也不保证遵循用户意图。

## 2. 一次优化步发生什么

```text
读取一批 token 和标签
    ↓
前向计算：得到 logits
    ↓
交叉熵：比较预测与真实标签
    ↓
反向传播：计算各参数的梯度
    ↓
优化器更新：改变参数，清理或重置梯度
    ↓
记录指标，继续下一批
```

最简单的梯度下降写作 `θ ← θ − η∇θL`。实际大模型训练常使用 AdamW 等优化器，并配合学习率预热、衰减、梯度裁剪与混合精度。梯度累积允许多个微批次合成一次更新，应按有效 token 等规则正确缩放损失。

训练期间会周期性保存 checkpoint。要可靠地恢复训练，除了权重，还可能需要优化器、学习率调度器、随机数状态、数据读取位置和配置。仅保存推理权重不等于保存了完整训练状态。

## 3. 为什么训练比“把权重放进显存”贵

训练显存不仅包含权重，还包含梯度、优化器状态、激活以及临时通信缓冲区。常见优化手段解决的是不同问题：

| 方法 | 主要作用 | 代价或限制 |
| --- | --- | --- |
| 混合精度 | 降低部分计算与存储成本 | 需要稳定的数值策略 |
| 激活重计算 | 少存中间激活 | 反向时额外计算 |
| 数据并行 | 各设备处理不同样本 | 同步梯度；朴素方式会复制模型状态 |
| 张量并行 | 把大矩阵等计算分到多卡 | 对设备间通信要求高 |
| 流水线并行 | 把不同层分到不同设备 | 调度复杂，可能有流水线空泡 |
| 状态分片 | 分摊参数、梯度或优化器状态 | 需要通信和相应框架支持 |

这些技术可以组合使用。没有一个“参数量 × 固定系数”的显存公式能覆盖所有训练配置。

## 4. 一个帮助理解预算的粗算

对稠密 Transformer 的常规训练，常用 `C ≈ 6ND` 粗估主要训练 FLOPs：`N` 为参数量，`D` 为训练 token 数。例如教学设定 `N=10⁹`、`D=2×10¹⁰`，则约为 `1.2×10²⁰ FLOPs`。

这不是显存公式，也不是直接的训练时间。长上下文的注意力成本、重计算、通信和设备利用率都会影响实际耗时；MoE 还需区分总参数与激活参数。相关预算权衡可参考 [Chinchilla](https://arxiv.org/abs/2203.15556)，不应把某个实验条件下的比例当作所有项目的硬规则。

## 5. 训练过程中看什么

- **训练与验证损失**：是否下降、是否分离；验证集要与训练分布及目标任务相匹配。
- **数值稳定性**：梯度异常、NaN、损失突增。
- **系统效率**：有效 token/s、通信开销、设备利用情况、失败恢复。
- **能力评测**：语言、代码、知识及目标领域能力，防止单看平均损失。
- **数据审计**：数据混合比例、重复和测试污染。

困惑度 `PPL = exp(L)` 在 `L` 为自然对数平均交叉熵时成立。不同 tokenizer 或评测语料下的 PPL 通常不能直接横向比较。

继续预训练是在已有 checkpoint 上继续做语言建模，可用于领域适配；它仍需要独立评测，避免领域收益伴随通用能力退化。

# 05 · 后训练与适配：从续写能力到助手行为

[← 上一章](04-预训练.md) · [返回目录](README.md) · [下一章 →](06-推理与部署.md)

## 1. 预训练模型为什么还需要后训练

给基座模型一句“新同事如何申请 GPU”，它可能回答，也可能接着写一份题目或网页内容。后训练通过示范、偏好或奖励，把已有能力导向期望的行为。

后训练不是唯一固定顺序。一种典型路线是“基座 → SFT → 偏好或强化学习优化”，也可以混合数据、多轮迭代，或直接使用已完成后训练的模型。

## 2. SFT：学习高质量示范

监督微调（Supervised Fine-Tuning）给模型输入与期望输出，例如：

```text
用户：根据制度，列出 GPU 申请步骤，并引用条款。
助手：1. 填写资源申请单……〔制度第 3 条〕
```

它通常继续使用 token 交叉熵，但训练分布变成任务与对话样本，并常常只对助手部分计算损失。数据必须展示真正希望模型执行的行为：依据不足时说明缺口，引用可验证的来源，遵守要求的格式。

SFT 能教会行为模式，也可能改变知识与能力，但不能保证可靠地保存、更新每一条企业事实。若制度频繁变化，仍应考虑通过检索提供当前版本。

## 3. 偏好优化：比较哪个回答更好

偏好样本通常包含同一个问题以及两个回答：`(x, y_w, y_l)`，分别表示更受偏好与较不受偏好的回答。

**经典 RLHF 路线**先用偏好训练奖励模型，再用 PPO 等方法优化语言模型。常用参考策略约束抑制过大的行为偏移。奖励模型只是偏好的代理，仍可能被策略钻空子。参见 [InstructGPT](https://arxiv.org/abs/2203.02155)。

**DPO**直接利用偏好对和参考模型构造损失，不需要在该训练步骤中显式训练一个奖励模型并执行 PPO。它仍然更新模型参数，也仍然依赖偏好数据质量。参见 [DPO](https://arxiv.org/abs/2305.18290)。

**基于可验证奖励的强化学习**可以根据测试用例、数学答案校验器等打分。在常见在线设置中，模型生成候选，评分器给出奖励，再用于更新策略。奖励设计不充分时，模型可能获得高分却没有完成真实目标。

这些方法是不同的优化路线，不是每个模型都必须依次经过的步骤。

## 4. LoRA 解决“怎么更新”，不定义“学什么”

全参数微调更新大量原有权重。LoRA 冻结基础权重，在选定线性层增加低秩增量：

$$W'=W+\frac{\alpha}{r}BA$$

其中 `A` 的形状为 `[r,d_in]`，`B` 为 `[d_out,r]`，秩 `r` 远小于相应维度。训练的是增量参数，推理时可按支持方式加载 adapter 或合并权重。

LoRA 可以用于 SFT，也可以用于某些偏好或强化学习训练；它与训练目标属于不同维度。它减少可训练参数和相应优化器状态，但基础权重与激活仍占显存。QLoRA 进一步结合量化基础权重等技术，不能简单理解为“所有训练运算都用 4 bit”。参见 [LoRA](https://arxiv.org/abs/2106.09685) 与 [QLoRA](https://arxiv.org/abs/2305.14314)。

## 5. 用什么方式适配内部助手

| 需求 | 首先验证的方案 | 需要留意 |
| --- | --- | --- |
| 回答今天更新的制度 | RAG 提供当前文档 | 检索、版本、权限和引用 |
| 稳定输出指定 JSON | 指令、示例、约束解码 | 语法正确不等于字段内容正确 |
| 持续遵循领域表达与任务规范 | 在基线评测后考虑 SFT | 代表性数据和能力回归 |
| 让回答更符合可标注的偏好 | 偏好优化 | 标注一致性与偏好偏差 |
| 改进有可靠验证器的任务 | 考虑奖励驱动的优化 | 奖励漏洞和分布外泛化 |

这些方法可以组合。是否引入训练，应由可复现的收益、数据条件和成本决定。
